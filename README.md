# Hot Streak — เวอร์ชันเล่นบนมือถือ

เกมแข่งมาสคอต + แทงพนัน สำหรับ 2–8 คน เจ้ามือคุมเกมจากคอม/แท็บเล็ต
(เหมือน Kahoot) ไม่ได้เล่นเอง ส่วนผู้เล่นแทงพนันผ่านมือถือของตัวเอง
ไพ่ในมือเป็นความลับรายคน ส่วนสนามแข่งกับสำรับหงายเห็นพร้อมกันบนจอเจ้ามือ

สำรับไพ่ 53 ใบและ side bet 12 ใบ ตรงตามของจริงในกล่อง

---

## เริ่มเล่นใน 2 นาที

```bash
npm install
npm start
```

เทอร์มินัลจะพ่นลิงก์ออกมา ให้ **เจ้ามือเปิดลิงก์นั้น + `/board.html`** บนคอม/แท็บเล็ต
(เช่น `http://192.168.1.50:3000/board.html`) แล้วกด **"สร้างห้องใหม่"**

จอเจ้ามือจะโชว์ **QR code** ของห้องนั้น ให้ผู้เล่นสแกนจากมือถือตัวเอง
สแกน → ใส่ชื่อ → เข้าห้องทันที ไม่ต้องพิมพ์รหัส 4 ตัวเอง

เจ้ามือไม่ได้เป็นผู้เล่น ไม่ต้องใส่ชื่อ ไม่มีไพ่ ไม่แทงพนัน — มีหน้าที่กด
เริ่มเกม / เปิดไพ่ / ไปเรซถัดไป ให้ผู้เล่นเท่านั้น

## เลือกวิธีโฮสต์

### 1 · เล่นในออฟฟิศ — ไม่ต้องโฮสต์อะไรเลย

```bash
npm start
```

รันบนโน้ตบุ๊กตัวเอง ทุกคนต่อ Wi-Fi วงเดียวกัน สแกน QR จบ
ฟรี ไม่ต้องสมัครอะไร เร็วที่สุด **แนะนำอันนี้ถ้าทุกคนนั่งอยู่ออฟฟิศเดียวกัน**

ถ้าเพื่อนเปิดไม่ติด มักเป็นไฟร์วอลล์บนเครื่องคุณ:
- **macOS** → System Settings › Network › Firewall › Options › อนุญาต Node
- **Windows** → ตอนรันครั้งแรกจะมี popup ถามให้กด "Allow access" เลือก Private networks

### 2 · มีคนอยู่คนละที่ — เจาะ tunnel

```bash
npm run tunnel
```

จะได้ลิงก์ `https://xxxx.trycloudflare.com` มาทันที ส่งลิงก์นี้ให้ใครก็ได้
ฟรี ไม่ต้องสมัครบัญชี ลิงก์อยู่จนกว่าจะกด Ctrl+C

ครั้งแรกอาจต้องสั่ง `npm install cloudflared` ก่อน (ถ้าตอน `npm install` มันโหลดไม่สำเร็จ)
ถ้าเจาะไม่ผ่าน สคริปต์จะสลับไปโชว์ลิงก์ Wi-Fi ให้แทนอัตโนมัติ

### 3 · อยากให้เปิดค้างตลอด — deploy

**Render** (ฟรี ง่ายสุด) — push โค้ดขึ้น GitHub แล้วใน Render กด
New › Blueprint › เลือก repo นี้ ไฟล์ `render.yaml` จัดการที่เหลือให้เอง
*ข้อควรรู้: แพลนฟรีจะหลับหลังไม่มีคนใช้ 15 นาที ตื่นครั้งแรกช้าราว 1 นาที*

**Docker** (ถ้ามีเซิร์ฟเวอร์บริษัทอยู่แล้ว)

```bash
docker compose up -d
```

ถ้าอยู่หลัง reverse proxy ให้ตั้ง `PUBLIC_URL` ใน `docker-compose.yml` ด้วย
เช่น `https://games.digimusketeers.co.th`

**Railway / Fly.io** — ใช้ `Dockerfile` เดียวกันได้เลย ไม่ต้องแก้อะไร

> ทั้ง 3 วิธีใช้โค้ดชุดเดียวกัน ไม่ต้องแก้ไฟล์ — QR ในล็อบบี้จะสร้างลิงก์ตาม URL
> ที่คนเข้ามาจริง ๆ ให้เอง ไม่ว่าจะเป็น LAN, tunnel หรือโดเมนจริง

## เข้าห้อง

เจ้ามือเปิด `/board.html` แล้วกด **สร้างห้องใหม่** จะได้รหัส 4 ตัว + QR
(หน้าบอร์ดนี้แหละที่มีหน้าที่กดเริ่มเกม/เปิดไพ่/ไปเรซถัดไป — เจ้ามือไม่ใช่ผู้เล่น)
ผู้เล่นสแกน QR หรือใส่รหัสจากมือถือตัวเอง ถ้ามือถือดับหรือรีเฟรช จะกลับเข้าห้องเดิมอัตโนมัติ
ถ้าจอเจ้ามือรีเฟรชหลุด ใส่รหัสห้องเดิมที่หน้า `/board.html` เพื่อกลับมาคุมต่อได้

## ลำดับการเล่น

| เฟส | เกิดอะไรขึ้น |
|---|---|
| เดิมพัน | snake draft ตั๋วคนละ 2 ใบ หยิบแล้วเลือกด้าน ปลอดภัย/เสี่ยง ทันที |
| ใส่ไพ่ | ทุกคนแอบเลือกไพ่ 1 ใบใส่สำรับ เห็นแค่บนเครื่องตัวเอง · เรซ 3 เลือกตั๋วคูณสองด้วย |
| แข่ง | เจ้ามือกด "เปิดไพ่ใบต่อไป" หรือเปิดโหมดอัตโนมัติ เซิร์ฟเวอร์คำนวณทุกอย่างให้ |
| จ่ายเงิน | สรุปตั๋วของแต่ละคน พร้อมคำตอบ side bet |

จบ 3 เรซแล้วดูยอดเงินรวม แล้วเปิดตาราง life outcomes ในคู่มือกระดาษอ่านกัน

## สำรับไพ่ (53 ใบ)

**ไพ่มาสคอต 44 ใบ** — ตัวละ 11 ใบเหมือนกันหมด ต่างกันแค่ทิศ swerve

`Recover Then 2` (ไพ่เริ่มต้น ขอบพิเศษ อยู่ในสำรับทุกเกม) · `Fall Down` · `Turn Around` ·
`3` · `2` · `-2` · `Star` · `1/2/3 Then Swerve` · `Recover Then 1`

**ไพ่เขียว 9 ใบ** (มีผลทุกตัว ชนกันไม่ได้ ข้ามเส้นชัยไม่ได้)

`Recover Then 2` · `Recover Then 3` · `1` ×2 · `2` ×2 · `3` ×2 · `-2`

### ทิศ swerve คือหัวใจของการ DQ

Gobbler กับ Hurley ปัด**ขวา** ส่วน Dangle กับ Mum ปัด**ซ้าย** เรียงเลนแบบนี้:

```
เลน 0        เลน 1        เลน 2        เลน 3
Gobbler  →   Hurley   →   ← Dangle     ← Mum
```

ตอนวิ่งหันหน้าถูกทาง ทุกตัวจะปัด **เข้าใน** เสมอ ตกขอบไม่ได้
แต่พอโดน `Turn Around` ทิศจะกลับด้าน — ตัวริมสนาม (Gobbler, Mum) ที่โดนหันหลังแล้วเจอไพ่ swerve จะปัดตกขอบทันที
นี่คือกลไกหลักของการถูกปรับแพ้แบบออกนอกสนาม เอนจินจำลองตรงนี้ไว้ครบ

## สิ่งที่เซิร์ฟเวอร์คำนวณให้อัตโนมัติ

- เดินตามตัวเลข / ไปดาวดวงถัดไป (ข้ามเส้นชัยได้)
- ล้ม → เคลื่อนที่ได้ทีละ 1 ช่อง (คลาน), ล้มซ้ำ = โดนน็อก DQ
- หันหลังกลับ → ตัวเลขบวกพาถอยห่างเส้นชัย, ทิศ swerve กลับด้าน
- ชน → ตัวที่หยุดนิ่งล้ม ตัวที่วิ่งอยู่ไม่เป็นไร
- ไพ่เขียว → มีผลทุกตัวพร้อมกัน ชนกันไม่ได้ ข้ามเส้นชัยไม่ได้
- สำรับหมด → พับสนามไปเส้นทึบถัดไป ตัวที่ตกค้าง = DQ แล้วสับใหม่ เผา 3 ใบ
- จบเรซเมื่อ 3 ตัวเข้าเส้นชัยหรือ DQ ตัวที่ 4 ได้อันดับที่เหลือ
- ตัดสิน side bet ทั้ง 12 ใบ รวมข้อที่ต้องเฝ้าดูตลอดเรซ เช่น "ล้มพร้อมกัน 2 ตัว",
  "คลานในช่วงสุดท้าย", "ช่วงสุดท้ายว่างตอนที่ 1 เข้าเส้นชัย"

## ปรับแต่ง

แก้ที่ `src/data.js` ที่เดียว (client อ่านคอนฟิกสนามจากเซิร์ฟเวอร์ ไม่ต้องแก้ซ้ำ)

| ตัวแปร | ใช้ทำอะไร |
|---|---|
| `TRACK.length` / `TRACK.start` | ความยาวสนามและจุดสตาร์ท |
| `TRACK.stars` | ตำแหน่งดาวในแต่ละเลน |
| `TRACK.sectionLines` | เส้นทึบแบ่งสนาม ใช้ทั้งตอนพับเสื่อและนิยาม "ช่วงสุดท้าย" |
| `MASCOT_TICKET_VALUES` / `SIDE_TICKET_VALUES` | เงินรางวัลบนตั๋ว |

หลังแก้ ให้รัน `npm run sim` จำลอง 2,000 เกม ดูว่าอัตราชนะ ช่วงเงิน และอัตราตอบ "ใช่"
ของ side bet แต่ละใบยังสมดุลอยู่ (ถ้าใบไหนต่ำกว่า 8% หรือเกิน 92% จะมีคำเตือนขึ้น)

```bash
npm run sim    # จำลองสมดุล 2,000 เกม
npm run e2e    # ทดสอบผู้เล่น 4 คนผ่าน socket จริง
npm run demo   # เล่น 1 เรซแล้วเล่าออกมาเป็นข้อความ พร้อมวาดสนามให้ดู
```

`e2e` กับ `demo` ต้องเปิด `npm start` ค้างไว้อีกหน้าต่างก่อน

## จุดที่ตั้งใจเปลี่ยนจากของจริง

1. **จุดสตาร์ทตั้งไว้ที่ช่อง 2** — ถ้าตั้งชิดขอบท้ายกว่านี้ ไพ่เขียว `-2` ใบเดียว
   จะ DQ ทั้งสนามตั้งแต่ไพ่ใบแรก (เจอตอนจำลอง)
2. **กันเรซค้าง** — เมื่อพับเสื่อครบทุกเส้นแล้ว การสับใหม่ครั้งถัดไปจะบีบสนามทีละช่อง
   เพื่อไม่ให้เรซวนไม่รู้จบ กรณีนี้เกิดยากมาก แต่กันไว้ก่อน
3. **ข้อความ life outcomes และประวัติมาสคอต** ไม่ได้ใส่ในแอป — เป็นงานเขียนของ CMYK
   เปิดคู่มือกระดาษอ่านตอนจบเกมได้
